# Daily cockpit navigation and editing patterns

Reviewed 2026-07-23 from current official or first-party product sources.
Repository-reference audit: 2026-07-28.
Patterns are evidence, not templates.

| Question                      | Evidence                                                                                                                                                                                             | Adopt                                                                                                                           | Reject                                                                                                                         |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Top-level navigation          | Apple defines tabs as stable top-level navigation, not actions, recommends labels and fewer tabs; current YNAB begins on Home and separates Home, Plan, transactions, accounts, and reflection.      | Four stable labeled destinations: Home, Budget, Activity, Plan. Adapt the same order to a desktop sidebar.                      | Quick Log as a tab; hiding tabs by context; Account consuming a daily-use tab.                                                 |
| First screen                  | Copilot leads its dashboard graph with “Free to Spend,” then review and budget snapshots. YNAB Home leads with actionable alerts and priorities, then month summary.                                 | Lead with the selected-period budget answer, then one action, attention, supporting totals, recent activity, and wrap.          | A collage of equal metrics, imported-transaction review, referrals/content, or bank-balance language.                          |
| Add/edit transaction          | YNAB keeps Add Transaction directly available; Apple sheets are for short, scoped tasks tied to current context.                                                                                     | One non-stacked Fast Log sheet for amount, category, title, note, and secondary date; reuse it for explicit edit/delete.        | Chat parsing, stacked category sheet, swipe-only correction, or a long configuration modal.                                    |
| Category creation/maintenance | Monarch preserves category order across lists and retains deactivated categories for reactivation. Copilot distinguishes budget-bearing categories from non-budget tags.                             | One canonical category system; inline create returns to Fast Log; dedicated management handles rename/order/role/color/archive. | A second label/tag taxonomy or deleting historical categories.                                                                 |
| Budget editing                | Monarch shows Budget/Actual/Remaining and uses a deliberate editing surface.                                                                                                                         | Readable status by default, Category Detail for one item, explicit batch Edit Budget for many allocations.                      | Permanent input-grid density on the daily status screen.                                                                       |
| Sheets versus pages           | Apple frames sheets as brief interruptions for focused tasks, not navigation.                                                                                                                        | Sheet for Fast Log; pages for status, structural management, batch edits, wrap, and plan sub-surfaces.                          | Nested modal navigation or multi-step tax/category administration in a sheet.                                                  |
| Offline and install           | web.dev requires useful offline behavior and warns not to assume service-worker control on first load. WebKit uses manifest `display: standalone`; `apple-touch-icon` takes precedence when present. | Honest first-online bootstrap, then IndexedDB-first daily use; standalone manifest, full icons, explicit install guidance.      | Pretending first-device auth is offline, relying on `beforeinstallprompt`, Background Sync, or Cache Storage for private JSON. |
| Safe areas                    | WebKit requires `viewport-fit=cover` plus `env(safe-area-inset-*)` padding so full-width navigation does not hide content.                                                                           | Safe-area-aware top chrome, bottom tabs, Quick Log, and keyboard-height sheet.                                                  | Fixed bottom UI that assumes zero inset or a static viewport height.                                                           |
| Updates                       | web.dev describes a service-worker lifecycle in which an update may wait before activation.                                                                                                          | Preserve the user-triggered “Update ready · reload” lifecycle so an edit is not replaced mid-task.                              | Surprise `skipWaiting`/reload during an entry.                                                                                 |
